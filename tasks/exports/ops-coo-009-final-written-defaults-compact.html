Part 2 - Risk Tiering

Every output gets two passes [Assumed]: action value and risk. Action value scores revenue proximity, time sensitivity, source confidence, owner clarity, effort size, and learning value on a 0/1/2 scale [Assumed]. Risk flags are irreversible customer commitment, strategic relationship, public/brand risk, legal/privacy/security, financial exposure, novelty, and low source confidence.

Green: value >= 7 [Assumed], source verified, reversible, known pattern, no red flags. Examples: verified existing-page SEO fixes, approved-template Flash repurposing, approved non-strategic Cyborg follow-up, and Alfred internal briefings.

Yellow: value >= 5 [Assumed] or uncertainty without CEO-specific risk. Owner review handles domain judgment; expert councils handle high-value ambiguity like creative refreshes, channel pivots, SEO positioning, or paid media calls.

Red: Eric only. Pricing, refunds, contracts, strategic accounts, public claims, legal/privacy/security, senior people decisions, new core crons, killing core crons, or CEO-level priority tradeoffs. Operational Experience

My operating pattern is turning ambiguous work into gates. In the M365 -> Google Workspace migration, work spanned mail, calendar, DNS, aliases, OneDrive/SharePoint, Missive, GHL, phone routing, Windows identity, and Microsoft cleanup. I installed one control center with lane state, accepted/gated status, rollback rules, and a hard rule that cleanup could not run until dependency gates passed.

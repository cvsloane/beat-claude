# Ops COO 009 - Attachment Map

Use this as the plain-language reviewer guide if the portal allows multiple uploads, or as the cover page if the proof files are merged into one appendix.

## Upload Hierarchy

The reviewer path should stay lean. Do not make the first reader sort through the full internal proof stack.

| Tier | Files | Rule |
|---|---|---|
| Required answer | `written-answer.pdf`, `ai-usage-disclosure.md`, `candidate-profile.md` | Submit wherever the application explicitly asks for the challenge answer, AI usage disclosure, profile, or self-assessment. |
| Core proof | `operating-artifact.md`, `evidence-log.md`, `attachment-map.md`, `heaviside-rpe-profitability-redacted-summary.md`, `heaviside-sales-delivery-automation-redacted-summary.md`, `heaviside-org-chart-redacted-summary.md` | Include if the portal allows supporting files or if merging into one appendix. These are the strongest role-relevant proof files. |
| Application support | `cover-letter.md`, `application-answers.md` | Use for the application form and cover-letter field. Do not upload unless the portal asks for those fields/files. |
| Appendix only | `heavisideos-slack-eval-redacted-summary.md`, `hermes-cron-fleet-redacted-summary.md` | Include only if the upload surface supports a clean appendix. These strengthen AI/workflow and cron-fleet credibility, but should not distract from GM economic proof. |
| Backup / walkthrough | `job-post-line-scorecard.md`, `challenge-compliance-audit.md`, `hermes-closed-loop-agent-proof.md`, x-accel, decision council, SloaneVault memory, raw screenshots, raw exports | Hold for interview, public site, or follow-up unless requested. Do not attach raw confidential material. |

If the portal is cramped, submit the required answer plus the core proof in this order: written answer, operating artifact, evidence log, RPE/profitability proof, sales/delivery automation proof, AI disclosure, candidate profile.

| File | What it proves | Why it matters |
|---|---|---|
| `written-answer.pdf` | Main response to the COO Operations Challenge. | Required answer; fits the written cap. |
| `operating-artifact.md` | Queue states, risk gate, CEO operating contract, cron audit, dashboard, memory schema, cadence, failure modes. | Shows the operating system a reviewer can inspect. |
| `evidence-log.md` | Claim-to-proof mapping with source labels and proof tiers. | Keeps numbers and proof disciplined under `SCORING.md`. |
| `ai-usage-disclosure.md` | Tools used, what AI helped with, what Chris decided, and what was checked. | Required disclosure; separates AI help from human judgment. |
| `candidate-profile.md` | LinkedIn, MMPI-style operating profile, and founder/talent-leadership model. | Required profile/self-assessment material; also addresses leadership-bench fit. |
| `cover-letter.md` | Concise application cover letter. | Use in the cover-letter field if available. |
| `application-answers.md` | Draft answers for agency experience, day-to-day AI usage, and permanent process/system improvement. | Use for application form fields and interview consistency. |
| `heaviside-rpe-profitability-redacted-summary.md` | Heaviside revenue/FTE and net margin improved together from P&L/FTE model. | Primary GM economic proof. |
| `heaviside-sales-delivery-automation-redacted-summary.md` | HG Market Report and HG SEO Commander as real sales/delivery automation systems. | Built-system proof; time savings remain estimate-labeled. |
| `heaviside-org-chart-redacted-summary.md` | Public roster plus functional ownership map across technical operations, web, SEO, PPC, operations, client success, and reporting/admin. | Supports talent leadership, delegation, leadership bench, and founder-leverage claims. Not for FTE validation. |
| `heavisideos-slack-eval-redacted-summary.md` | Before/after Slack assistant eval and retrieval improvement. | Optional measured AI workflow proof; attach only if the packet can support one more proof file cleanly. |
| `hermes-cron-fleet-redacted-summary.md` | `88` repo-checked Hermes/open-agents jobs with routing, status, pause/error visibility, and fleet health checks. | Bounded cron-fleet operating proof; use as backup or walkthrough evidence. |
| `job-post-line-scorecard.md` | Line-by-line scoring against the GM job post's exclusion and strong-candidate language. | Internal QA; prevents generic scoring. |
| `challenge-compliance-audit.md` | Requirement-by-requirement audit against the challenge parts, win criteria, lose criteria, and public scoring standards. | Internal QA; confirms the packet follows the prompt exactly. |
| `hermes-closed-loop-agent-proof.md` | Source-backed summary of Hermes as an outputs-to-outcomes operating layer across research, content, infra, inbox, fleet, and cold-email jobs. | Backup proof / public-page source material. |
